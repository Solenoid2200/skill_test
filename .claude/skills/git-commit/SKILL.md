# Git Commit

1. Проверь `git status` и отдельно изучи staged, unstaged и untracked изменения. Прочитай diff выбранных файлов; для untracked-файлов изучи содержимое до добавления.
2. Сгруппируй изменения по смыслу и выбери ровно один логически связанный набор файлов. Покажи выбранный список файлов. Не включай несвязанные изменения и не используй `git add .` или `git add -A`. Если подходящую группу нельзя определить безопасно, уточни у пользователя и не коммить.
3. Подготовь краткое сообщение в формате Conventional Commits: `type(scope): description` (scope можно опустить, если он неуместен). Добавь только выбранные пути в staging и проверь staged diff и итоговое сообщение; не затрагивай уже staged изменения вне выбранного набора.
4. Создай ровно один коммит с проверенным сообщением. Не выполняй `git push`, не используй `--amend` или `--no-verify`. Если коммит не удался, сообщи об ошибке и не утверждай, что он создан.
5. После успешного коммита проверь результат и верни полный hash коммита, точное сообщение и список закоммиченных файлов.
